# Contributing

## Basic workflow

```text
main
↓
feature branch
↓
development
↓
commit
↓
push
↓
Pull Request
↓
review
↓
merge into main
```

Create a focused feature branch from `main`, make and test your changes, then open a Pull Request for review. Do not commit experimental work directly to `main`.

Example branch names:

- `feature/frontend-dashboard`
- `feature/backend-api`
- `feature/ai-anomaly`
- `feature/database`
- `feature/map`
- `feature/auth`

## Commit messages

Use Conventional Commit-style messages, for example:

- `feat: add dashboard`
- `fix: correct priority calculation`
- `docs: update setup instructions`
- `chore: initialize project`
